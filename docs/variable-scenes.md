# 可变机位场景入口

本文保留最初六机位实验记录。当前运行方法、输入格式和质量检查已升级，以[通用运行器](general-runner.md)为准。

`scene_fusion/` 是从原始照片和 PLY 开始的新入口，来源数量由清单决定，不依赖旧 `four-room` 标定、collider 或 V3 网格。历史四机位入口保留，未将其所有旧脚本改名或覆盖。此次实际端到端测试是六机位；2、4、6、9 来源的清单与标签维度另外通过单元测试，不应把这些单元测试说成其他数量均经过真实场景验证。

## 输入与输出

同目录中的 `1.png` 和 `1.ply`、`2.png` 和 `2.ply` 等自动配对。支持 JPG/JPEG/PNG，也支持历史 `{id}_7680.jpg`；每个 PLY 必须只有一个匹配照片。需要至少两个有空间重叠且可匹配的拍摄位置。照片为完整 2:1 等距柱状全景，无需 EXIF 相机参数。当前 PLY 读取器支持已验证的14个float字段、binary little endian Gaussian格式；不支持任意网格PLY或未经转换的高阶SH格式。

每个场景使用独立输出目录与输入 SHA-256 清单。数量、路径或文件内容变化将阻止复用旧缓存。不要将输出放入原片目录。`four-room/scenes/<scene-id>` 中的 `four-room` 是既有HTTP服务的数据根目录名称，不代表限定四个来源。

输出 `final/fused.ply`、`final/fused.splat`、标定/配准/分区报告，以及 `result.json`；播放器 `/scene-room.html?scene=<scene-id>` 按清单生成 N 个机位和空间近邻中点。公开仓库只存代码和聚合指标，照片、模型、缓存与截图留在本机。

## 流程

1. 每张原图对自己的完整原始 PLY 做特征匹配与相机标定，检查留出匹配；通过高斯实际像素贡献筛除自身完全不可见的点。
2. 全部 N(N−1)/2 对照片做双向特征匹配，深度仅用于初始化相似变换。未经验证的边不进入初始化图；图不连通则失败，不猜机位。
3. 球面多视图轨迹联合优化相机姿态/位置。首相机与一条基线确定规范自由度，绝对长度仍非测量尺度。整条轨迹留出验证。
4. 由训练轨迹重新估计各原始 PLY 尺度。可选 `--depth-warp` 使用有照片约束的局部径向深度场，保持来源射线，按 Jacobian 传输完整协方差；变形后必须重渲染深度。该变形是实验选项，不保证所有场景都获益。
5. 按距离、入射角与可见性竞争负责区域；被近层遮挡的相机不能接管背后点。多视图自由空间冲突抑制浮层。当前选用单个获胜来源，保留原始高斯参数；并非把所有来源半透明叠加，也未执行旧网格流程的 alpha-expansion。高斯足迹会越过分区边界，不能声称重叠严格为零。
6. 512 → 1024 多分辨率联合拟合颜色、受限位置/尺寸/朝向/透明度；保覆盖并限制中点偏离初始结果。邻接颜色/位移约束沿用受限高斯训练器。来源照片参与拟合，不能把拟合分数当作独立新视点精度。
7. 同时比较初始融合和完整原始 PLY。后者使用固定原始 alpha 掩码，避免已有裁切破洞被掩盖。最后导出后逐值读取 PLY 核对，并实际检查浏览器。

## 原生 Windows 运行

需要此前验证的 CPU Python 环境，以及 PyTorch/CUDA/gsplat GPU 环境。`run-refit-gpu.ps1` 加载本机 Visual Studio 与 CUDA；其他机器须调整相应路径。此次 GPU 环境额外安装了 `opencv-python-headless==4.10.0.84`，未修改系统 Python。

在仓库根目录运行，所有路径参数可替换：

```powershell
& C:/path/to/cpu-env/Scripts/python.exe scene_fusion/pipeline.py `
  --inputs C:/scene-inputs `
  --out four-room/scenes/new-scene `
  --gpu-python C:/path/to/gpu-env/Scripts/python.exe `
  --depth-warp `
  --serve-root C:/path/to/served-root
```

`--serve-root` 可省略，只生成结果。发布时输出必须实际位于服务根目录的 `four-room/scenes/<scene-id>`，也可通过既有目录联接访问。scene-id 使用字母、数字、下划线或连字符。当前参数 `--resume` 按阶段校验内容、代码及参数后恢复。默认不启用局部深度场；本次最初六组实验启用了它。

完整入口将实验产物导出并标为实验版，不等于自动质量验收。需要查看报告中的来源、中点和近景。生成深度误差、反射、弱纹理、未观测表面及动态物体依然可能失败。计算量随匹配对数和高斯数增长，并不意味着无限机位可在当前显存内运行。

## 本次六机位结果

6 张 7680×3840 PNG + 6 份原始 Gaussian PLY，总输入 3,051,998 个高斯。每来源可见性保留 2,627,200 个，最终融合 1,043,373 个。

15 对匹配中 13 条边通过初始化验证；球面束调整形成 959 条轨迹，其中 768 训练、191 留出。留出中位等效像素误差 1.15970 → 0.65894，P90 4.93995 → 3.86299。此为3840宽ERP定义的角度等效量，不是原始7680图的统一实际像素误差。

最终54个视向 = 36个来源方向 + 18个空间近邻中点方向。1024检查中，同一初始掩码 SSIM 0.87503 → 0.95216；36个来源方向均改善，初始高覆盖区域新增 alpha<0.5 像素为0。完整原始PLY固定掩码另测：原始平均SSIM 0.95187，融合 0.95336；37,263,905个原始高覆盖像素中新增低透明度像素0。这个阈值不检测错误颜色、重影或所有缺损。

512复核：SSIM 0.84655 → 0.94370，36方向均改善，新增低透明度像素0。没有中点实拍真值；目视中点的桌边、线缆、灯和局部表面仍有毛糙。六组原片与旧四组不是同一次初始化，不用上述分数宣称“六组必然胜过四组”。

比较过仅体素分区、可见性领地、局部深度场后再拟合。体素版出现明显电视重层，没有作为默认。可见性领地与照片联合拟合显著减轻该问题；本轮没有用统一掩码与相同高分辨率训练预算严格分离局部深度场的收益，因此该步骤仍为可选项。本次选择深度场 + 高分辨率联合拟合候选，保留各试验产物用于核查。

测试：17项CPU单元测试，包含可变来源数、缓存污染拒绝、无观测来源不可接管、径向射线不变与Jacobian有限差分；PLY往返逐值一致；浏览器单场景加载、15个按钮、无运行时异常并保存实际WebGL画布。
