# 通用全景与 PLY 重建流程

`run-reconstruct.ps1` 将已认可的自适应平滑与平滑优先两种方式固化为
可重复运行的独立预设。输入为 N 组对应的完整全景与 Gaussian PLY，N≥2。
不要求六个机位、不要求连续编号、不假定顺时针或闭环排列。

## 输入与启动

在一个目录中用相同文件名配对，例如 `入口.jpg / 入口.ply`、
`中间.png / 中间.ply`、`窗侧.jpg / 窗侧.ply`。兼容旧的
`名称_7680.jpg / 名称.ply`。每份 PLY 必须恰好匹配一张照片。
照片为完整 2:1 等距柱状全景，分辨率可以不同。

目前输入读取器支持带完整 Gaussian 属性的 SH0 PLY，兼容属性重排及
ASCII / 大小端二进制。非零高阶 SH 会明确拒绝，避免忽略方向颜色。
普通 XYZ 点云、Mesh PLY 和 SPZ 不能冒充该输入。输出单一高斯支持 SH2。

原生 Windows 上配置 `scene_fusion/settings.local.json`：CPU Python、
CUDA/gsplat Python、Open3D Python，以及已有播放器的 `serve_root`。
示例见 `settings.example.json`；Mesh 环境依赖见 `requirements-mesh.txt`。
GPU 构建包装仍使用 `run-refit-gpu.ps1`，换机器需配置对应 CUDA / VS 环境。

```powershell
# 固化后的主入口：默认同时生成两种 Mesh
.\run-reconstruct.ps1 -Inputs 'D:\新场景输入' `
  -OutputDirectory 'D:\预览根目录\four-room\scenes\my-room'

# 仅检查图片与 PLY，不开始 GPU 处理
.\run-reconstruct.ps1 -Inputs 'D:\新场景输入' `
  -OutputDirectory 'D:\预览根目录\four-room\scenes\my-room' -Check

# 中断后恢复；参数或输入变化必须使用新输出目录
.\run-reconstruct.ps1 -Inputs 'D:\新场景输入' `
  -OutputDirectory 'D:\预览根目录\four-room\scenes\my-room' -Resume
```

`-Mode adaptive` / `-Mode smooth` 可只生成一种。`-Plan` 输出实际阶段、
参数与依赖；`-Profile smoke` 是低分辨率、极少训练步数的流程测试，
不能用于判断最终画质。默认 `standard` 保存完整训练与重建参数。

贴图默认启用用户认可的“小范围投影冲突分区”，同时用于两种几何预设。
需要与此前分区算法比较时，加 `-LegacyTexturePartition`，并使用新输出目录。
流程配方版本已升为 2；旧运行不会被静默改写或按新参数继续。

## 自动流程

1. 检查输入配对、内容哈希、格式和尺度；各照片对自己的 PLY 恢复拍摄相机。
2. 全体机位两两匹配，深度支持的 Sim(3) 鲁棒估计，空间分布与留出点验证；
   最大可信连接初始化，全局相似变换优化，再用全景轨迹束调整和深度尺度拟合。
3. 由验证通过的匹配边建立相机图：空间最小生成树保证连接，再加有匹配
   证据的近邻边。弱全局边剔除后若不连通，停止并提示补拍重合区域，
   不按编号连环、不把空间上靠近但没有匹配的相机硬连起来。
4. 保留原始 PLY 与相似变换，按 49% 规则生成漫游监督，训练一个静态 SH2
   高斯；增加细节视向及交接采样，评估原机位和留出视点，再导出单一 PLY。
5. 从该单一高斯渲染深度；保边深度平滑、TSDF 临时表面、有限碎片清理及
   补面；采样表面点，平滑位置和法线，输出重建用 `geometry-guide.ply`。
6. 自适应 / 平滑优先低频重建、Taubin 平滑、微小数值焊接；按可见性
   选择原照片负责区域，将有充分可见性支持的小范围投影冲突区域统一到
   一个照片来源，只在相容窄接缝中羽化，导出 Mesh 与高清贴图。
7. 自动生成原机位、相机图路线与斜视检查，输出报告、哈希及预览入口。

“PLY 磨皮”处理的是从高斯深度提取的带法线表面点云，**不是直接把所有
高斯中心当成真实表面进行平均**。最终会同时保留可播放高斯 PLY 与普通
几何引导 PLY，二者字段、用途不同。高清贴图不能恢复被磨掉的几何细节。

相机图反映观测关系，不能保证两点间直线可以穿行；复杂多房间布局还需要
碰撞 / 通行路线规划。文件名只决定稳定的显示编号与坐标参考，不是拍摄顺序。
图连接和几何拟合不要求各相机都与其余每一台直接重合，但整体必须连通。
未提供实测尺寸时，恢复的是相对位置和模型尺度，不宣称输出单位就是米。

## 固定预设与产物

| 预设 | 相对体素 | Poisson 深度 | Taubin 次数 | 边缘保留 |
|---|---:|---:|---:|---|
| adaptive | 0.004 | 9 | 3 | 至少两张照片边缘支持的高密度样本 |
| smooth | 0.004 | 8 | 12 | 更均匀地降低几何采样 |

这些是相对尺度的算法预设，不含灯、电视、地球仪的位置或物体名称。
不会对每个新场景手工指定球心、平面或编号区域。原始输入与旧输出保持不变。

默认冲突分区沿网格扩展 3 圈；单块面积最多占有效表面总面积 2%，
必须有同一张照片支持整块区域，才统一来源。它更改照片归属，不增加面或补洞。
当前六机位已认可结果为 `mesh-conflict-photo-six-v1`：调整 151 个区域，
2,816 个三角面的归属（约 0.83%）。这是保守分区，不是最高强度。
灯边仍有投影错位；加重法线磨皮的实验没有被采纳。增加分区范围需要单独
比较薄物体、遮挡和斜视，不能把降低可见性要求作为增强手段。

```text
my-room/
  recipe.json                     输入哈希、完整命令、固定预设
  run-state.json / logs/           阶段状态、断点校验与错误
  calibration/                    相机标定、匹配、束调整与相机图
  native/                         原始 PLY 漫游
  single/final/fused.ply           独立单一高斯
  single/evaluation/              原机位 / 留出视点及局部画质诊断
  depth-smooth/                   平滑后的合成深度
  guide/geometry-guide.ply        平滑几何引导点云，非高斯
  adaptive/                      Mesh、OBJ、MTL、贴图、ZIP
  smooth/                        Mesh、OBJ、MTL、贴图、ZIP
  audit/                         网格拓扑与斜视射线检查
  result.json / index.html        全部结果入口与质量状态
```

预览入口：`http://127.0.0.1:7870/four-room/scenes/my-room/index.html`。
输出必须位于已运行服务器的公开目录才能通过浏览器访问。
播放器支持安全的分层场景路径，拒绝 `..`、反斜线及空路径段。

## 资源与恢复

原始教师模型按需加载，GPU 缓存上限为两份；监督图像在线渲染，不保存
随所有路线视图增长的完整浮点图像体。总运行时间仍随相机、匹配对和
高斯数量增加，源模型和最终单一模型仍须能被当前设备处理，不能理解为
无限机位 / 无限点数。两两匹配为 O(N²)，大规模场景需要额外检索分组。

断点记录检查脚本、参数、上游产物及输出内容。目录检查只跟踪该阶段产物，
后加的浏览器诊断截图不会触发重建；已跟踪文件损坏会触发重算。失效或
中断阶段的独立输出移入本次运行的 `attempts/`，不删除旧尝试。

## 验收边界

完成流程与画质验收分开。相机匹配 / 束调整证据不足会停止；训练后若
原机位保真门槛不通过，结果页明确标记，允许查看候选但不自动成为新基线。
拓扑闭合、射线不漏空、照片误差等必须结合可视化判断，不能代表真实扫描精度。

本次验证包含独立双机位合成输入的端到端 smoke 流程；稀疏分叉、乱序以及
2/3/5/8/11 机位的图构建测试；乱序稀疏图 Sim(3) 求解和既有可变数量回归。
这证明入口与数据关系已通用化，不证明所有房间都能达到会议室相同画质。
最新实测记录位于 `experiments/2026-11-13-reconstruction-workflow/`。
