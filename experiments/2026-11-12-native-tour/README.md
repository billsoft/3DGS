# 原始模型连续漫游实验

目标是扩大此前用户接受的原机位保真播放范围，并提供机位间平滑移动。此实验不生成新的融合 PLY，也不把图像渐变描述为几何配准修复。

## 改动

- 沿相邻机位连线，纯原始区域从间距的 8% 扩大到默认 38%，提供 30% / 38% / 44% 选项。38%–62% 是直接从原始模型 A 到 B 的图像渐变，不再切回旧融合模型。
- 每个来源独立渲染，保留原始 Gaussian 参数。透明度只用于完整渲染图像的合成。
- 在机位邻接图上选择最短路线，分段移动；鼠标和移动键可中断。路线图不等于碰撞网格。
- 默认停止平移后逐渐选择一个来源。这个补充来自中点实测：两份原始电视几何不一致，长期 50/50 混合仍有双影；单来源驻足能去掉这种重复轮廓。
- 按需预载和淘汰闲置模型；所有来源数量和机位坐标来自同一个 `native.json`。

## 验证

Windows 上使用六份原始 PLY。输入和现场截图不纳入公开仓库。

首次浏览器检查覆盖六个机位的水平、向上、向下，共 18 张截图；与独立加载单份原始 PLY 的同视点参考相比，最大单图平均绝对误差为 **0.0185385 / 255**，单像素最大通道差超过 5 的像素比例最高 **0.041754%**。这验证了原始 PLY 的渲染保真，不代表与原照片无差异。

沿 1–2 号机位连线检查 10 个位置。30% 处仍是起点原始模型，50% 为等权图像渐变，70% 为终点原始模型。目视发现 50% 处电视重影，因此加入默认的驻足单来源模式。在相同中点、不移动眼点的对照截图中，驻足后电视恢复为单个轮廓。

可复现脚本：

```powershell
node tests/test_native_tour.mjs
node tests/test_native_camera.mjs
node tests/test_room_look.mjs
node tests/test_room_sorting.mjs
# 以下复用任务开发浏览器 CDP 19346 和本地 7870 静态服务
node tests/check_native_tour.mjs
node tests/check_native_tour_navigation.mjs
python tests/compare_native_reference.py four-room/scenes/native-source-six-v1 --actual tour-browser --out four-room/scenes/native-source-six-v1/tour-browser/comparison.json
```

浏览器输出位于私有数据目录 `tour-browser/`。`check.json` 记录原始机位、沿线采样、真实机位移动及原地转头；`navigation.json` 记录驻足选择、键盘移动、多段路线与中断检查。最终导航检查结果应以对应 JSON 的 `passed` 为准。

补充导航检查已实际确认：中点停留后变为单一来源、W 沿水平面移动、1→2→3→4 路线到达精确机位、返程可用鼠标中断且停止漂移为零。本次开发浏览器使用软件 GPU，长路线超过了最初 180 秒的 CDP 等待上限；没有重置或跳到终点，而是继续观察同一条运行中的路线直至到达，再执行中断检查。续验结果保存在 `navigation.json`，此前通过的中点/键盘断言记录在 `tour-navigation.log`。复现脚本的等待上限已调整为 600 秒，并在长路线前保存检查点。该检查不作为真实 GPU 帧率的性能承诺。

## 边界

默认 38% 是播放策略的选择范围，不是通过全场景验证的准确几何半径。移动中的短暂双影仍可能存在；远离采集路线、物体背面和遮挡区域仍可能暴露单份原始模型的缺陷。本版没有使用光流形变、重新贴图或网格重建。
