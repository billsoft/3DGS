# 公共几何根因试验：有局部改善，尚非通用发布版

本次从 `general-six-v2` 的同一批六份输入、同一组相机标定出发。没有替换已接受的旧四图基线。自动检测器没有使用物体名称、人工框选或本房间坐标；但仅在一个自动候选平面上得到清楚的改善，不能据此宣称任意房间可用。

## 证据与根因

1. 原始 PLY 在其来源相机看屏幕清楚，融合后出现薄片、条纹。已有相机 BA 的留出中位误差为 0.6515 个 3840 宽全景等效像素。相机定位误差没有排除，但无法单独解释全部局部退化。
2. 从三张照片中自动匹配的四边形估计公共平面后，各 PLY 对应区域需要不同径向深度修正。六份模型中被修正点的中位径向差约为 0.250、1.034、1.289、1.400、0.824、0.519 个归一化模型单位。它们是相对于候选平面的诊断值，并非测量真值或米。
3. 该平面拟合两个机位、检查第三机位时，平均误差 3.9523、最大 6.6411 像素（1024 方形视图）。原严格门槛 3.5/6 未通过。只有显式 `--allow-provisional` 才允许以实验门槛 5/8 生成本次预览；没有把门槛放宽包装成严格验证通过。
4. 对应区域沿来源射线投影至共同平面并用 Jacobian 变换完整协方差后，外轮廓改善，但保留原点结构和多来源颜色仍有条纹。运行 2800 步拟合后仍不够好，拒绝作为推荐候选。
5. 在相同候选公共平面上重新采样，按视角和投影分辨率自动选一个主来源照片，结果中间视点轮廓、内部纹理明显改善。其余几何原样保留，因此门边、支架等残留也仍存在。
6. 实际浏览器中还复现了独立的显示问题：跳转视角后尚未完成排序时，投影布出现大片彩色污斑、向上视图出现黑区。对相同模型和同一相机姿态等待完整排序后消失。播放器原默认位置触发阈值为 1 个世界单位，并存在渐进排序；`runSplatSort()` 返回只表示提交，不能当作工人线程已完成。新增 `room-sorting.js` 对相机变化合并请求并补一次完整排序，避免小距离移动或快速跳转停留在旧排序/可见点集合；测试等待实际完成后才截图。

这支持两个相互独立的问题：独立生成模型的局部深度不一致；即使移到公共表面，原有高斯足迹和来源间外观差异仍可能产生条纹。屏幕的反射随拍摄位置变化，单一 DC 颜色的静态 PLY 不能同时正确再现全部反射。单主来源能避免平均混色，但反射将固定在该来源外观。

## 对照试验

| 方法 | 结果 | 决策 |
|---|---|---|
| 六源预测深度的公共 TSDF 表面 | 563480 个三角形；部分墙连续，屏幕仍破裂成层 | 拒绝；预测深度不能当可靠扫描直接平均 |
| 射线保持的平面投影 + 全协方差变换 + 2800 步拟合 | 轮廓改善，内部仍有多来源条纹 | 拒绝作为最终候选 |
| 公共有界平面重新采样 + 单来源附色 | 目视屏幕明显改善；其他区域残留不变 | 独立局部修复预览，不升级默认基线 |
| 图像梯度细化边界 | 严格验证仍未通过；还能产生组合轮廓假候选 | 不替换本次约束，记录局限 |

## 实际验证

- 最终 1464515 个高斯：保留原融合非目标区域，删除 17276 个旧点，在公共平面生成 404438 个点。
- 原生 PLY 固定透明度掩码：36 个来源视向，37264106 个高覆盖像素，没有新增低透明度孔洞。
- 原始单张 PLY 平均 SSIM 0.951726；最终候选 0.951536。此前六图融合约 0.952937：**总平均拟合分数略降，局部中间视点外观改善**。不能用平均 SSIM 代替几何检查。
- 自动来源回归门槛通过；严格公共平面门槛未通过。二者独立，不混为一个发布许可。
- 静态 PLY 导出回读逐值一致。候选 SHA256：`e085a5982252cf9abbc59cf617aa66ca4a591631b55c1d85795ee761e49c80da`。
- 相同视点离线对照包括来源水平、两处中点、向上、向下。另用任务专属浏览器验证 WebGL 加载、6 个来源按钮、邻近中点及单模型渲染。
- 31 项 Python 测试、3 项异步排序测试通过。排序测试覆盖提交与完成区别、连续相机变化合并、排序期间再次变化及取消。
- 原片、模型、截图、检测坐标只保存在本机忽略目录，不进入公开仓库。

## 实验入口

各模块读取场景清单，不假设四图、六图或环绕顺序。平面约束至少需要三个有对应证据的机位；不足时不做该修复。

```powershell
python scene_fusion/planar_constraints.py --source <scene> --out <detections>
python scene_fusion/verify_planes.py --scene <scene> --observations <detections>/quads.json --out <constraints.json> --free-quads
python scene_fusion/resample_planes.py --source <scene> --model <same-scene-optimized.npy> --planes <constraints.json> --out <candidate>
```

`source.npy` 必须与模型点的顺序一致。默认严格约束为空时停止，不偷偷用原始生成深度补一个平面。`--allow-provisional` 只允许显式运行放宽门槛的研究对照，不能作为生产默认。`apply_planes.py`、`surface_volume.py`、`surface_export.py` 保留为消融试验工具，不接入默认流程。

## 还缺什么

角点一致不能证明整个内部属于同一表面：边框可能由不同深度物体组合而成。后续必须加入内部多视图几何支持、遮挡边界和复合轮廓拒绝；非平面物体需要不同的公共表面约束。未知背面不能由羽化或透明度优化可靠恢复。本轮没有解决整房间全部几何、门边絮状物、细杆和反射。

相关原始项目供方法依据，不表示本轮复现其完整系统：

- [PGSR](https://zju3dv.github.io/pgsr/)：平面化高斯和几何约束。
- [GSFusion](https://github.com/ethz-mrl/GSFusion)：几何融合与高斯表示的结合。
- [Open3D RGB-D integration](https://www.open3d.org/docs/latest/tutorial/pipelines/rgbd_integration.html)：有深度观测时的 TSDF 融合。
- [LIMAP](https://github.com/cvg/limap)：多视图线段几何。
