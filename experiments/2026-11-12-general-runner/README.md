# 可变数量通用入口回归

测试入口：原生 Windows `run-scene.ps1`，默认可见性分区及两级照片联合拟合，未开启局部径向变形。

`integration.json` 由 `tests/collect_general_runs.py` 从真实完成的阶段状态、质量报告和导出检查生成。脚本重新验证候选哈希与所有原始输入的哈希；不上传照片、PLY、相机轨迹或截图。

测试范围：

- 同一实拍六机位数据的 2、4、6 来源子集，分别独立标定、匹配、束调整、分区、训练、评估及导出。它们不是三个不同实拍房间。
- 独立程序生成的六面纹理房间，两机位输入，中文名称与普通名称混合，原始 PLY 尺度因子分别 0.01 / 100，用于覆盖空间尺度与文件名变化。
- 23 项 CPU 单元测试，包括 2/4/6/9 来源清单与标签维度、PLY 格式和属性顺序、单位缩放、缓存损坏与参数变化、明确失败状态、局部画面退化与非法浮点证据拒绝。
- 实际浏览器加载单个融合场景，按 N 自动生成机位和近邻中点按钮，保存 WebGL 画布供人工核查。

此次集成中实际发现并修复：中文 UTF-8 元数据被 Windows 默认 GBK 解码；两机位部分立方体朝向没有匹配轨迹时调用空 remap；重标定后继续使用旧特征或旧完整 PLY 变换缓存。相比只改变列表长度，这些测试覆盖了数量与输入变化带来的流程错误。

六机位实际画面检查：来源灯具整体轮廓与桌边覆盖保留，桌面和地球仪可辨认；空调附近墙面、近物体边界仍可见涂抹、毛糙。来源分数是参与拟合视向的诊断，不能证明中点或隐藏表面几何正确。没有以这些结果宣称任意场景都能成功重建。

复核：

```powershell
python -m unittest discover -s tests -p 'test_*.py'
python tests/collect_general_runs.py --base four-room/scenes --report experiments/2026-11-12-general-runner/integration.json
```

第二条命令需要本机私有实验产物，公开仓库不包含这些模型。
