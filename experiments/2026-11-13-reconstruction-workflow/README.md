# 通用完整重建流程固化

用户认可自适应和平滑优先两种结果后，将二者登记为可用预设。
`accepted-presets.json` 绑定此前实际产物和 SHA-256；所有被接受的产物及
更早的 14 份基线产物复核未改动。旧算法、单一 PLY 和 Mesh 继续保留。

新入口 `run-reconstruct.ps1` 从 N 组原始照片 / PLY 自动运行 27 个阶段，
输出单一高斯、普通平滑引导 PLY 和两种贴图 Mesh。脚本没有私有会议室
目录、固定六机位索引或环形边列表。空间相邻图必须有全局匹配证据支持。

验证范围：

- 独立生成的双机位纹理房间，混合中文名称、输入 PLY 尺度比 10000；
  实际跑完 prepare、配准、束调整、尺度、蒸馏、平滑、重建、贴图和审计。
- smoke 使用 12+12 步训练、128 深度、1024 贴图；是流水线验证，不是
  高画质候选。原机位保真门槛未通过的状态如实展示，不能冒充质量验收。
- 2/3/5/8/11 个机位的稀疏星形 / 分叉 / 乱序图；空间上靠近但无匹配
  的分组明确拒绝连接。稀疏 Sim(3) 乱序后对齐参考坐标仍恢复正确相对姿态。
- 33 项相关 Python 回归通过：通用入口 6、位姿图 7、旧运行器 6、
  漫游蒸馏 5、贴图 9。目录内容损坏触发重算，新增诊断文件不触发重算。
- 两种 Mesh 的原机位方向和斜视浏览器检查；单一 PLY 页面仅请求一份
  PLY；原始漫游检查两机位保真、移动过渡及原地转头。

已有六机位实拍数据的配准报告通过新相机图筛选；本次没有宣称重新跑过
六机位标准分辨率全流程。更多数量和非环形结构已做算法测试，尚不能
据此宣称所有新房间的质量都通过验收。

完整运行记录由 `tests/collect_reconstruction_run.py` 从真实产物生成，
重新校验所有阶段内容及原输入哈希。照片、模型与渲染截图不进入公共仓库。

```powershell
python tests/collect_reconstruction_run.py --run four-room/scenes/reconstruct-smoke-v3 --out experiments/2026-11-13-reconstruction-workflow/integration.json
```
