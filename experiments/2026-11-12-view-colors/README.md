# 来源全景监督的视角相关颜色

本轮针对在原始机位向上、向下仍有云状灰斑的问题。此前增量候选和播放器实际上使用 DC 固定颜色；文件格式和播放链路没有使用方向相关球谐。现在训练、NPZ、完整 PLY 和浏览器均支持二阶 SH，不再经由丢弃高阶系数的 `.splat` 文件。

相机在同一光心转头，不会改变同一点到相机的方向。SH 的作用是允许不同光心看到同一点时有不同颜色；它不能恢复被裁掉的几何、修复遮挡或保证原机位像素完全保真。

## 算法和实验边界

- 冻结现有融合点的位置、旋转、尺度与透明度，只拟合 DC 和 8 个高阶系数，每系数 RGB 三通道。
- 所有来源全景转成六个透视方向，全部参与拟合，包括上方和地面。机位数量由数据集决定，没有四机位或六机位的索引假设。
- RGB、结构、梯度损失同时约束图像；新增低频颜色误差，避免只提高 SSIM 而改变平坦表面色调。
- 使用邻近距离、最短轴法线一致性和原有颜色差建立表面图，约束颜色变化和方向系数的邻接差。保留原有颜色差，不直接把所有点颜色平均。
- 可选保留上一轮独立验证过的公共表面外观。此次使用既有公共平面保护掩码，404,438 个点保持原 DC、方向系数为零；其余点学习 SH。没有添加按灯具、窗帘等语义类别绘制的补丁。
- 中间视点使用原候选作弱信赖约束，不当成真实照片。

## 消融和验收

第一轮未加邻接约束：原机位 SSIM 提升，但中点的公共平面出现细条纹，拒绝作为最终候选。

第二轮使用较强邻接约束：条纹减少，但部分方向的低频颜色偏差增加。原机位平均 SSIM 仍提升，说明平均指标不能代替局部色斑和中点的可视化检查。

第三轮降低邻接权重、加入原图低频颜色约束，保留已验证公共表面的外观。训练和固定视点结果记录在 `result.json`；照片和生成模型不进入仓库。

接入浏览器前又查到渲染差异：gsplat 1.5.3 内置 SH 路径只截断负值，当前浏览器在每个高斯上把颜色限制到 `[0,1]`，然后才进行透明度合成。现在使用可微 SH 求值并在合成前截断上下界，以匹配网页；新增高亮饱和顺序测试。前三轮属于该修正前的消融结果，最终候选重新拟合和评估，不能混用其报告。

`scene_fusion/native_audit.py --strict-source` 检查每个来源的六方向。参考是完整原始 PLY 的高覆盖掩码，比较照片误差、SSIM、低频色斑及局部图块；任意方向、局部图块退化或新增空洞均不能判为全面通过。这些阈值是显式工程诊断，不是像素相等保证。来源照片参与训练，中间视点没有独立实拍真值。

最终网页一致候选在上一版固定掩码上，平均 SSIM 从 0.951173 提升到 0.959680，36/36 方向整体 SSIM 改善，平均 RGB 误差从 0.010638 降到 0.009328（约 12.3%）。新增低覆盖空洞为 0，几何与透明度逐元素一致。

**严格原始 PLY 保真未通过**：27/36 方向仍有整体或局部指标退化，不能称为所有原机位无损。1 号位上方的低频颜色误差从 0.003491 降为 0.001472，但地面从 0.002768 变为 0.002953；后者仍残留碎纹和遮挡边缘缺陷。独立预览保留上一版入口，不作为新验收基线自动替换。

## 复现入口

使用 GPU 环境执行 `scene_fusion/view_color_fit.py --data <dataset> --model <DC.npy或SH.npz> --out <独立输出>`。本轮最终阶段采用 `--steps 3200 --dc-lr .001 --sh-lr .002 --graph-weight .3 --blotch-weight 2 --reference <上一版.npy> --protected-appearance <已验证表面mask.npy>`。它是在已有标定和融合几何上的外观拟合阶段，不代替配准或公共表面重建。

网页一致性阶段继续运行 3200 步，`--dc-lr .0005 --sh-lr .001 --graph-weight .1 --blotch-weight 3`，同样保留公共表面外观。完整参数保存在独立输出的训练记录中。

`scene_fusion/export_view_color.py` 要求同一模型的来源审计和评估文件；检查几何、透明度不变以及完整 SH PLY 往返一致。PLY 使用 INRIA 的通道优先 `f_rest_*` 排列。`tests/check_sh_renderer.py` 验证零高阶系数与旧 RGB 渲染一致，并检查视线方向符号。

`tests/check_refit_browser.mjs --diagnostic-poses --check-look-in-place` 验证真实浏览器加载的系数阶数、shader 阶数、开启 SH 是否实际改变画面、完整排序及在当前机位抬头不跳回第一机位。浏览器仅使用任务自己的既有 CDP 会话。

实际网页测试发现另一个独立根因：默认 OrbitControls 围绕目标点旋转，俯仰限制为 `[0.1, 0.75π]`。仅修改 target 再调用 update，也会把相机移离拍摄光心。实测在最后一个机位点击抬头，相机偏移约 0.74 个模型单位。因此此前“位于原机位”的俯仰观察并不可靠。新增 `room-look.js`，拖动改为原地转头，检查按钮保留光心，解除原俯仰范围限制并禁止轨道旋转；WASD/QE 平移保持原有用途。`tests/test_room_look.mjs` 验证光心不变，浏览器测试通过真实鼠标拖动再次检查。

上游实现：[gsplat](https://github.com/nerfstudio-project/gsplat)、[GaussianSplats3D](https://github.com/mkkellogg/GaussianSplats3D)。当前播放器最多启用二阶 SH。
