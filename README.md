## 算法

1. 深度重投影后的双向 DIS 光流，检查遮挡、双向一致性和三角化误差。
2. 以空间块留出对应点验证表面法向位移；平滑正则、位移上限和翻转冻结保护几何。
3. 对公共表面做一致细分、射线可见性检查，以 alpha-expansion / max-flow 划分四个照片来源与未知区域。
4. 区域内部单一来源，只在表面邻接的窄接缝带中，对颜色、深度和对应点一致的样本羽化。
5. 受限照片 RGB 增益/偏置校正，再沿表面传播受限接缝颜色偏置。
6. 弱证据且与有效初值冲突时保留原贴图；删除无依据的灰色占位面，重新采样表面高斯。

新优化层无灯具专用模板；初始化仍含此前电视、球体、桌面拟合先验。灯具锯齿、背面缺失、桌底空洞尚未解决。删除错误几何可能增大空洞。网格贴图预览不含 PLY 的局部颜色偏置和窄带羽化。

## 通用保边细节试验

`fusion_next/run_detail.py` 使用已接受基线的几何和区域归属，按原图梯度及投影像素跨度分配采样，在边缘法向收缩高斯足迹，并只融合接缝低频颜色。没有灯具或窗帘专用贴图、分割区域或合成形状。

先将已接受输出目录完整另存到 `four-room/baselines/2026-11-11-fusion-next/`。这份私有缓存需包含 `geometry.npz`、`ownership.npz`、`prior.npz`、`correspondences.npz`、`seam-offset.npy`、各阶段 JSON 报告以及基线 `fused.ply` / `fused.splat`。然后在上述 Python 环境与 `GS_INPUT_DIR` 设置下运行：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe fusion_next/run_detail.py --validate --serve-root .
```

结果写入独立的 `four-room/fusion-detail/`，预览地址为 `http://127.0.0.1:7870/fusion-detail-room.html`；已接受的基线入口保持不变。可用 `--smooth` 显式试验保边法向平滑，但默认关闭：消融试验没有发现值得默认改变基线几何的收益。平滑无法修复缺失表面和错误拓扑，边缘优化也无法保证消除所有灰色污染。

验证包含固定近景、四个中点、7 个原图来源视向；后者只在共同高覆盖率像素上计算 SSIM 和 MAE，不将其解释为所有漫游视点的画质。每来源采样预算上限为 1.8 倍；高斯数量增加会提高浏览器内存与加载成本。

## 相机领地与原始 PLY 裁切试验

`fusion_next/run_territory.py --validate --serve-root .` 在上述相同私有输入和冻结基线缓存上，生成独立的 `four-room/fusion-territory/`。不会重建相机标定，也不是仅给四张照片就能运行的完整产品入口。脚本顺序执行领地分割、原始高斯裁切、接缝校色、射线锚定、公共表面导出及窄缝补点；`--validate` 验证公共表面候选并打包网格。

领地综合标定光心距离、可见性和观测质量；核心锁定，在表面邻接带内优化接缝。搜索带为 0.22、保留重叠带为 0.055，均为当前场景模型单位，不是米。裁切会限制近缝高斯足迹，不能保证所有椭球完全不跨界。每机位裁切结果是 `cropped-2.ply` 至 `cropped-5.ply`。

预览 `http://127.0.0.1:7870/fusion-territory-room.html` 默认展示公共表面领地版；`?source=2` 等查看单份裁切；`?view=raw` 查看原始核心直拼，`?view=anchored` 查看射线锚定，`?view=painted` 查看原图重新附色，`?view=hybrid` 查看窄缝补点。后四项是诊断候选，不代表质量逐级提高。报告链接中部分候选对照图属于本次额外实验产物，主入口不会自动重算所有候选验证。

本轮没有替换已接受基线。公共表面版部分桌面细节改善，但灯具破碎仍在；原始高斯裁切及锚定候选在中点存在明显空洞、噪声与形变。补点减少局部透明裂缝，不能纠正错误表面。固定来源视点分数不能证明漫游质量，更不能据此修补未观测的背面。本次 aggregate 数值记录见 `experiments/camera-territories/`，照片、模型及渲染不提交。

## 覆盖保护与局部回退

`fusion_next/run_coverage.py --serve-root .` 从冻结基线及上一节已生成的 `fusion-territory/ownership.npz`、`effective-ownership.npz` 提取来源提案。先生成 `fusion-coverage-wide`，再以多视图颜色误差回退到 `fusion-coverage-guarded`，最后渲染、审计和发布。依赖相同标定与私有输入，不适用于直接换一组照片。

该轮不裁点，不移动点，不改透明度、协方差及点顺序，只改变通过证据检查的颜色。因此覆盖与基线严格相同；已存在的空洞仍然存在。相机领地只对质量接近的来源提供优先权，不能强制低质量来源接管。接管需满足深度、置信度、颜色差、对应点距离；随后要求至少两个可信照片观察的平均误差下降，任何可信观察的误差增加低于限制。

本次放宽提案更新 13,680 个点，其中 11,637 个被逐点回退，只保留 2,043 个。对两处灯、电视背面和7个来源视向做逐像素 alpha 对比，并检查4个机位中点；新增空洞为0。额外在真正发生变化的像素上比较照片误差，避免全图均值掩盖局部退化。通过检查不代表未知视点全部正确，也不代表达到明显视觉提升；结果整体接近已接受基线。灯具破碎及未观测背面没有修复。

预览 `http://127.0.0.1:7870/fusion-coverage-guarded-room.html`；绿/灰诊断显示实际改色/未改色范围，不是四相机领地图。基线与领地试验页面保持独立。公开的本次参数和审计记录在 `experiments/coverage-guard/`，照片和模型仍不提交。

## 原始机位保真诊断与播放

`fusion_next/run_native.py --serve-root .` 需要此前同房间的标定、领地缓存，以及 `four-room/baselines/2026-11-11-coverage-guard/` 完整基线。它保存仅经过相似变换的四份原始高斯，进行四机位×六方向测试，再运行保留高斯形状的领地直拼、单向遮挡筛除和有观测支持的补洞消融。该入口不解决新房间的初始标定。

参考改为完整原始 PLY 在自身拍摄点的渲染。变换前后24方向一致性测试用于排除坐标变换自身损失；它不证明跨机位注册准确。静态补洞候选平均源视图 SSIM 为0.8942，高于已接受融合基线的0.8452，但相对原始高斯新增空洞仍为7,005像素，基线为1,726像素（24幅384×384测试图的总数）。电视仍有错误遮挡，故静态候选未通过验收。全图指标改善不能覆盖局部严重错误。

`fusion-native-room.html` 是明确分开的视点相关播放器，不是新的单一 PLY。在机位附近完整显示对应原始高斯，在中点使用已接受基线；原始模型不裁点、不改形状、不重新附色。两个渲染器共享相机，在屏幕上渐变过渡，避免把两份几何合为新高斯层。原始模型权重在最近机位间距的8%内为1、24%以外为0。阈值是工程参数；仅原始机位有直接保真依据，过渡带可能出现双影，中间区域的几何缺陷依然存在。单一主循环先决定来源、再渲染，跳过不参与显示的渲染器。内存需求仍高于单模型。

验证策略函数可运行 `node tests/test_native_anchor.mjs`。独立测试浏览器的CDP端口19346打开预览后，运行 `node tests/check_native_browser.mjs` 检查四机位端点、中点回退和模式按钮；加 `--screenshots` 可读回两个 WebGL 画布，但软件渲染环境可能超时。不是控制用户日常浏览器的脚本。公开指标位于 `experiments/native-fidelity/`；原照片、高斯和截图不提交。预览与诊断不会替换已接受基线。
